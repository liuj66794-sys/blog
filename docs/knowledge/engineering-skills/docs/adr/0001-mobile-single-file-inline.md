# 手机版采用单文件内联分发

工作区的页面需要能在手机上复习，但用户的真实使用路径是"微信文件助手 → 手机 Chrome"，该路径只能传输单个文件，既带不走 `assets/` 目录（样式丢失、页面退化为纯文本），也保持不了页面间的相对链接。我们决定：桌面源文件保持不变，用一个可重复运行的构建脚本把每个 HTML 的样式与脚本全部内联，生成自给自足的单文件副本到 `mobile/` 目录；手机版放弃站内导航保障，使用方式为"一次传一课"。

## Considered Options

- **局域网本地服务器**（如 `python -m http.server`）：不改文件、整站可用，但每次学习前要开电脑起服务，离开同一网络即失效——不符合"躺床上复习"的场景。
- **部署到公网**（GitHub Pages 等）：随时随地可访问，但要求把私人学习工作区推上公网仓库，且依赖网络。
- **合并成单个巨型 HTML**：一次传输全站都在，但需要拼接脚本、改写全部内部链接，内容每改一次都要重新合并，工程复杂度高一档。

## Consequences

- `mobile/` 是生成物，不是事实来源；任何内容修改必须改源文件后重新跑构建脚本，手工编辑 `mobile/` 下的文件会在下次生成时被覆盖。
- 手机版页面间的站内链接不保证可用，这是有意为之，不是 bug。
- Google Fonts 的远程 `@import` 保留，手机无网时回退系统字体，不影响阅读。
