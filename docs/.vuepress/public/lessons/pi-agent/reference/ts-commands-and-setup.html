TS 命令与工程组织

这页是"命令与项目骨架"的压缩精华：卡住时先查这里，比翻课件快。

命令对照

命令作用何时用
node -v / npm -v打印版本号安装 Node 后验证环境
npm init -y生成 package.json开新项目的第一步
npx tsx 文件.ts转译并直接运行 TS日常运行，看输出
npx tsc --noEmit只检查类型，不运行验证类型是否全部通过
npm run 脚本名执行 scripts 里的命令别名项目的标准启动方式
tsx vs tsc · 分工 tsx 是运动员：转译 + 运行，看程序跑出什么；它不做类型检查，类型错了照样跑（比如跑出 NaN）。tsc --noEmit 是裁判：只检查类型，不产生任何输出——没有输出就是全部通过。两个都要会，谁也代替不了谁。

package.json 骨架

{
  "name": "项目名",
  "version": "1.0.0",
  "scripts": {
    "start": "tsx main.ts"
  }
}

scripts 给常用命令起别名；之后用 npm run start 代替手敲长命令。

tsconfig.json 骨架

{
  "compilerOptions": {
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "target": "ES2022",
    "strict": true,
    "noEmit": true,
    "esModuleInterop": true,
    "skipLibCheck": true
  }
}

有了它，npx tsc --noEmit 才知道按什么规则检查。strict: true 打开全部严格检查。

模块语法两行

// tool-types.ts —— 暴露
export interface Tool { /* ... */ }

// tools.ts —— 引入（./ 表示当前目录，省略会被当成 npm 包）
import { Tool } from "./tool-types";

常见报错速查

报错原因与对策
"不是内部或外部命令"装完 Node 后终端没重启——关掉所有终端窗口重开
类型错误但程序照跑你用的是 tsx（不查类型）；换 npx tsc --noEmit 看报错
找不到模块 "xxx"本地文件路径漏了 ./，被当成 npm 包了
