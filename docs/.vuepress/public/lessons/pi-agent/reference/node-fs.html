Node.js 文件系统（fs）

读写文件卡住时先查这里。只用 Promise 版 API：node:fs/promises。

两个核心 API

API签名返回行为
readFilereadFile(path, "utf-8")Promise<string>读出文件文本；文件不存在 → rejected
writeFilewriteFile(path, content, "utf-8")Promise<void>不存在则创建，已存在则覆盖（不追加、不备份）
import { readFile, writeFile } from "node:fs/promises";

const content = await readFile("notes.txt", "utf-8");
await writeFile("output.txt", content, "utf-8");

try / catch：接住 rejected 的 Promise

try {
  const content = await readFile("不存在的文件.txt", "utf-8");
  console.log(content);
} catch {
  console.log("读文件失败");   // 程序不崩，走到这里
}

read_file 工具骨架（Agent 设计：错误作为结果返回）

export const fileReader: Tool = {
  name: "read_file",
  description: "读取指定文本文件的内容",
  execute: async (args) => {
    try {
      return await readFile(args.path, "utf-8");
    } catch {
      return `错误：读不到文件 ${args.path}`;   // 不抛错，让模型看到原因
    }
  }
};

常见现象速查

现象 / 报错原因与对策
程序崩掉，报 ENOENT: no such file or directory读的文件不存在，Promise rejected 且没人接——用 try / catch 包住 await
打印出 <Buffer 61 62 63 ...>readFile 忘传 "utf-8"，拿到的是原始字节——补上编码参数
打印出 Promise { <pending> }忘了写 await——拿到的是小票不是文件内容
writeFile 后旧内容没了writeFile 是覆盖不是追加——真实 Agent 用 diff / 补丁机制保护现场
一句话记住 readFile / writeFile 都返回 Promise：await 取结果，try / catch 接失败；读文本永远带 "utf-8"，写文件记得它会覆盖。
