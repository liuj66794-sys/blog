# Node.js 文件系统：Agent 的手

这节课结束时，你的注册表里会多出两个**真实**工具：`read_file`（读文件）和 `write_file`（写文件）——不再是模拟，而是真正读写你磁盘上的文件。你还会学会用 `try / catch` 接住失败的 Promise，让工具失败时程序不崩。

Coding Agent 干的两件最基本的实事：**读代码**（理解现状）和**写代码**（应用修改）。打开 [pi-mono](https://github.com/badlogic/pi-mono) 的源码，`read_file`、`apply_patch` 这些工具的底层全是 Node 的 fs 模块。**PatchPilot 的第一批真实工具，从这节课长出来。**

:::

## 温故：先回忆，再学新内容

**1.（第 4 课）`await` 做了什么？它的"等"和同步的"等"差在哪？**

::: details 显示答案

`await` 暂停当前 async 函数，等 Promise 兑现后把结果取出来。关键区别：它**只暂停当前函数，不冻住整个程序**——程序其他部分照常运转；同步的等是把全程序冻在原地。

:::

**2.（第 4 课）Promise 有哪三种状态？读一个不存在的文件，Promise 会进入哪种状态？**

::: details 显示答案

`pending`（等待中）、`fulfilled`（已成功）、`rejected`（已失败）。读不存在的文件会失败 → `rejected`。这节课你会第一次亲眼见到它。

:::

**3.（第 3 课）import 本地文件和 import Node 内置模块，路径写法有什么区别？**

::: details 显示答案

本地文件路径以 `./` 开头（如 `"./tools"`）；省略 `./` 会被当成 npm 包或 Node 内置模块。内置模块习惯加 `node:` 前缀，比如今天要用的 `"node:fs/promises"`。

:::

## 1. readFile：把文件读进程序

Node.js 把读写文件的能力收在内置模块 `fs`（file system，文件系统）里。我们用它的 Promise 版本：

```
<code>import { readFile } from "node:fs/promises";

const content = await readFile("notes.txt", "utf-8");</code>
```

逐行读：

- `"node:fs/promises"`：`node:` 前缀表示"这是 Node 内置模块"；`/promises` 表示要它的 **Promise 版 API**——每个调用都返回 Promise，可以直接 `await`。第 4 课学的东西，立刻在真实 API 上用上。
- `readFile(路径, "utf-8")` 返回 `Promise<string>`，`await` 取出的就是文件的文本内容。
- `"utf-8"` 参数告诉它：把文件里的字节按 UTF-8 规则解码成文本。**不传这个参数，你拿到的是原始字节（Buffer）**，打印出来是一堆看不懂的数字。读文本文件，永远带上它。

## 2. writeFile：把内容写回磁盘

```
<code>import { writeFile } from "node:fs/promises";

await writeFile("output.txt", "Agent 的第一份文件！", "utf-8");</code>
```

规则只有一条，但很重要：文件不存在 → **创建**；文件已存在 → **直接覆盖旧内容**。不追加、不备份、不问你是否确定。

所以真实 Agent 的"改文件"工具从不直接整文件覆盖——它们用 diff / 补丁机制保护现场（pi 的 `apply_patch` 就是干这个的）。这是阶段 1+2 的内容，今天先记住：`writeFile` 会覆盖。

## 3. 失败是常态：try / catch 接住 rejected 的 Promise

第 4 课说过 Promise 会 `rejected`——读一个不存在的文件，就是最常见的 rejected。`await` 一张 rejected 的小票时，错误会被**抛出来**，没人接的话程序直接崩掉。接它的工具叫 `try / catch`：

```
<code>try {
  const content = await readFile("不存在的文件.txt", "utf-8");
  console.log(content);
} catch {
  console.log("读文件失败");
}</code>
```

逐行读：`try` 包住可能失败的代码；里面任何一句抛出错误，程序立刻跳到 `catch` 继续走，不崩。读不到文件时，你会看到"读文件失败"，而不是一屏红色报错。

::: info Agent 设计要点

工具失败不该让整个 Agent 崩掉。真实 Agent 的做法：**在工具内部 catch 住错误，把错误原因作为工具结果返回**——模型于是知道"这个文件读不到"，自己换条路走。你的 `read_file` 工具就按这个设计写。

:::

## 4. 动手：给注册表加两个真实工具

**第一步**，`tools.ts`：顶部加一行 import，再加两个工具：

```
<code>import { readFile, writeFile } from "node:fs/promises";

export const fileReader: Tool = {
  name: "read_file",
  description: "读取指定文本文件的内容",
  execute: async (args) => {
    try {
      return await readFile(args.path, "utf-8");
    } catch {
      return `错误：读不到文件 ${args.path}`;
    }
  }
};

export const fileWriter: Tool = {
  name: "write_file",
  description: "把内容写入指定文件（不存在则创建，已存在则覆盖）",
  execute: async (args) => {
    await writeFile(args.path, args.content, "utf-8");
    return `已写入 ${args.path}`;
  }
};</code>
```

注意 `fileReader` 的设计：失败时不抛错，而是把"读不到文件"作为结果返回——这就是上面说的 Agent 设计要点。

**第二步**，`main.ts`：注册两个工具，然后在 `main()` 里连起来用——先写、再读、再读一个不存在的：

```
<code>import { calculator, greeter, slowGreeter, fileReader, fileWriter } from "./tools";

const toolRegistry: Record<string, Tool> = {
  calculator,
  greeter,
  "slow-greeter": slowGreeter,
  "read_file": fileReader,
  "write_file": fileWriter,
};</code>
```

```
<code>// main() 里，slow-greeter 那行之后加：
console.log(await runTool("write_file", { path: "hello.txt", content: "Agent 的第一份文件！" }));
console.log(await runTool("read_file", { path: "hello.txt" }));
console.log(await runTool("read_file", { path: "不存在的文件.txt" }));</code>
```

::: warning 动手任务（验收清单）

1. 按上面两步改造 `tools.ts` / `main.ts`。
2. 运行 `npm run start`：依次看到"已写入 hello.txt"→ hello.txt 的内容 → 读不存在文件时的错误提示（**程序没有崩**，"全部完成"照常出现）。
3. 打开项目文件夹，确认 `hello.txt` 真的躺在磁盘上，内容对。
4. 运行 `npx tsc --noEmit`，确认没有任何输出。

**贴回给我**：① `npm run start` 的完整输出；② `hello.txt` 的内容；③ 一句话：`readFile` 返回 `Promise<string>`，如果在 main 里忘了写 `await`，你拿到的会是什么？

:::

## 小测

**1. `readFile("a.txt", "utf-8")` 的返回值是什么？**

- A. string 文本内容
- B. Promise&lt;string&gt;
- C. Buffer 原始字节
- D. boolean 成功与否

::: details 点开核对答案

**答案：B（Promise&lt;string&gt;）** —— readFile 是异步操作，返回 Promise&lt;string&gt;，要 await 才能拿到文本。

:::

**2. `readFile` 的 `"utf-8"` 参数起什么作用？**

- A. 指定文件的写入权限
- B. 指定读取的超时时间
- C. 指定文件的路径格式
- D. 把字节解码为文本

::: details 点开核对答案

**答案：D（把字节解码为文本）** —— "utf-8" 告诉 readFile 按 UTF-8 把字节解码成文本；不传则拿到原始字节（Buffer）。

:::

**3. `await readFile` 读一个不存在的文件，会发生什么？**

- A. Promise 变成 rejected
- B. Promise 一直是 pending
- C. 自动创建空文件再读
- D. 返回一个空的字符串

::: details 点开核对答案

**答案：A（Promise 变成 rejected）** —— 文件不存在时 Promise 进入 rejected 状态，await 会把错误抛出来，用 try / catch 接住。

:::

**4. `writeFile` 写一个已存在的文件，旧内容会怎样？**

- A. 在文件末尾追加内容
- B. 报错提示文件已存在
- C. 被新内容直接覆盖掉
- D. 自动备份旧内容再写

::: details 点开核对答案

**答案：C（被新内容直接覆盖掉）** —— writeFile 对不存在的文件会创建，对已存在的文件直接覆盖旧内容——不追加、不备份。

:::

**2. 不看正文：读一个文件时，Promise 的三种状态各自对应什么现实情况？**

::: details 显示答案

`pending`：磁盘还在读，结果没出来；`fulfilled`：读到了，拿到文件文本；`rejected`：读失败（比如文件不存在），await 会抛出错误，需要 try / catch 接住。

:::

::: info 面试怎么考

"Node 里怎么读文件？同步还是异步？""try/catch 和 Promise 是什么关系？"是常见问题。真正的加分项是讲设计："我的 read_file 工具用 fs/promises + await，失败时在 execute 里 catch 住，把错误原因作为工具结果返回给模型——这样模型能看到失败原因、自己调整策略，而不是整个 Agent 崩掉。"你今天的代码已经实现了这句话。

:::
