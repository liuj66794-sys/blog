# 搭好环境：第一个 TypeScript 程序

**阶段 0 · 模块 A（TypeScript 起步）· 第 1 课 ｜ 预计 30 分钟 ｜ 前置：无**

> 本文为站内全文版（已纳入搜索，随堂测为折叠核对）。随堂测可点击作答的交互版：[**打开讲义**](/blog/lessons/pi-agent/lessons/0001-typescript-setup-first-program.html){target="_blank"}

这节课结束时，你的电脑上将有一个能运行 TypeScript 的开发环境，并且你会亲手跑出第一个 TS 程序。这是整个课程唯一一次纯环境课——从下一课开始，每一课都有新知识。

::: info 为什么学这个 · Mission 关联

你的目标是 Agent 方向面试，而我们对标学习的开源项目 [pi](https://github.com/badlogic/pi-mono) 就是 TypeScript 写的，你自己的 PatchPilot 也要用 TS 写。**TypeScript 不是选修，是这门课的入场券。**面试时"你的项目为什么用 TS"是项目介绍的高频开场问题——本课结尾会给你答案的雏形。

:::

## 1. Node.js 是什么

JavaScript 这门语言原本只能"住"在浏览器里，操作网页。后来有人把它请了出来，让它能直接在你的电脑上运行——读文件、写文件、执行命令、开网络请求。这个"请出来"的运行环境，就是 **Node.js**。

想一想 Agent 要做什么：读你的代码文件、运行测试命令、调用模型 API——全是浏览器之外的活。这就是为什么 Coding Agent 普遍建在 Node.js（或类似运行时）之上。

**TypeScript** 则是给 JavaScript 加上了"类型标注"的升级版：写代码时就声明"这个变量是字符串""这个函数返回数字"，写错类型当场报错，而不是等程序跑起来才炸。对大型项目（包括你将读的几万行 pi 源码）来说，这是保命的东西。

## 2. 安装 Node.js

1. 打开 [nodejs.org](https://nodejs.org/)，下载 **LTS（长期支持版）** 的 Windows 安装包（.msi）。
2. 双击安装，一路 Next 即可，不需要改任何选项。安装包会同时装好 `npm`（Node 的包管理器，用来安装别人写好的工具）。
3. 装完后**关掉所有已打开的终端窗口**，重新打开一个 PowerShell 或 Git Bash，输入：

```
<code>node -v
npm -v</code>
```

如果两条命令分别打印出类似 `v22.x.x` 和 `10.x.x` 的版本号，说明安装成功。如果提示"不是内部或外部命令"，说明终端没重启，或安装未成功——把报错原样贴回来问我。

## 3. 第一个 TypeScript 程序

### 3.1 建一个练习目录

在任意位置（比如桌面）建一个文件夹，作为阶段 0 的练习场：

```
<code>mkdir ts-playground
cd ts-playground
npm init -y</code>
```

`npm init -y` 会在目录里生成一个 `package.json` 文件——它是这个项目的"身份证"，记录项目依赖了哪些工具、有哪些可运行脚本。现在先不管它的内容。

### 3.2 写代码

在 `ts-playground` 目录下新建文件 `hello.ts`，内容如下（建议手敲，不要复制——第一节课就建立肌肉记忆）：

```
<code>function greet(name: string): string {
  return `你好，${name}！欢迎开始 Agent 课程。`;
}

console.log(greet("同学"));</code>
```

逐行看懂它：

- `function greet(name: string): string` —— 定义一个叫 `greet` 的函数。`name: string` 是类型标注：参数 name 必须是字符串；冒号后的 `string` 表示这个函数返回字符串。这就是 TS 比 JS 多出来的部分。
- 反引号 ` 包起来的是**模板字符串**，里面的 `${name}` 会被替换成变量的值。
- `console.log(...)` —— 把内容打印到终端。调用 `greet("同学")`，把返回值打印出来。

### 3.3 运行它

Node.js 只认识 `.js` 文件，不认识 `.ts`——类型标注对它来说是天书。所以我们请一个"翻译官"：**tsx**，它能把 TS 当场翻译并直接运行。在 `ts-playground` 目录下执行：

```
<code>npx tsx hello.ts</code>
```

`npx` 的作用是：发现本地没有 tsx，就自动临时下载并运行它（第一次执行会花几十秒下载，需要联网）。如果一切顺利，你会看到：

```
<code>你好，同学！欢迎开始 Agent 课程。</code>
```

恭喜——你的开发环境已经ready，这是整个 PatchPilot 项目的地基。

::: warning 动手任务（验收清单）

1. 运行 `node -v`，确认版本是 v20 或更高。
2. 完成上面 3.1–3.3 的全部步骤，看到问候语输出。
3. **改一行代码**：把 `greet("同学")` 里的 `"同学"` 换成你自己的名字，重新运行，确认输出变化。
4. 再改一行：把 `name: string` 改成 `name: number`，重新运行——观察 tsx 报的错。**读懂报错信息**（它说了哪个参数、期望什么类型、实际给了什么），然后改回 `string`。亲眼见一次类型报错，比读十页解释都有用。

**贴回给我**：① `node -v` 的输出；② 第 3 步的运行输出；③ 第 4 步的报错信息（用你自己的话复述一遍它是什么意思）。我审查后会生成这节课的 learning record。

:::

## 小测

**1. Node.js 让 JavaScript 能做什么？**

- A. 在浏览器里面渲染网页
- B. 为图片批量添加滤镜
- C. 在浏览器外运行 JS
- D. 网页自动翻译成中文

::: details 点开核对答案

**答案：C（在浏览器外运行 JS）** —— Node.js 让 JS 走出浏览器，能在本地读文件、跑命令——这正是 Agent 的运行底座。

:::

**2. 本课程选 TypeScript 的核心原因是？**

- A. TS 的运行速度更快
- B. 笔面试只考 TS 语法
- C. TS 还能代替数据库
- D. 目标项目用 TS 写成

::: details 点开核对答案

**答案：D（目标项目用 TS 写成）** —— 这是面试“项目为什么用 TS”的标准答案雏形：对标项目即 TS，且 Node 的工程能力与 Coding Agent 高度重合。

:::

**3. `npx tsx hello.ts` 中 tsx 的作用是？**

- A. 把 TS 打包成 JS
- B. 直接运行 TS 文件
- C. 检查 TS 类型错误
- D. 下载 TS 的依赖包

::: details 点开核对答案

**答案：B（直接运行 TS 文件）** —— Node 不认识 .ts，tsx 负责当场翻译并执行；类型检查、打包、装依赖是其他工具的事。

:::

**4. `package.json` 文件里记录的是？**

- A. 项目的依赖与脚本
- B. 项目的源代码文件
- C. 系统的环境变量表
- D. Node 版本列表

::: details 点开核对答案

**答案：A（项目的依赖与脚本）** —— package.json 是项目身份证：依赖清单 + 可运行脚本。后面安装工具、写测试命令都会改它。

:::
