# 异步与 async/await

## 1. 为什么程序需要"等"

你去餐厅点菜，有两种等法：

- **同步**：站在柜台前一动不动，直到菜做好端给你。这期间你什么都干不了。
- **异步**：拿到一张小票就离开柜台，该干嘛干嘛；菜好了凭小票取餐。

你之前写的程序全是同步的：一行执行完才执行下一行。这在 `calculator` 这种纯计算里没问题，但 Agent 的场景全是"要等"的事：

- 调模型 API：等网络往返，几百毫秒到几十秒
- 读文件：等磁盘响应
- 跑命令：等子进程结束

如果用同步方式等网络，整个程序就冻住了。所以 TypeScript 程序必须学会"拿小票"——这就是异步。

## 2. Promise：未来结果的凭证

那张"小票"在 TypeScript 里叫 **Promise**：一个代表"未来才会有的结果"的对象。它只有三种状态：

| 状态 | 含义 |
| --- | --- |
| `pending`（等待中） | 菜还在做，结果还没出来 |
| `fulfilled`（已成功） | 菜好了，拿到结果 |
| `rejected`（已失败） | 厨房出事了，拿到错误 |

下面这个函数造一张"指定毫秒后自动兑现的小票"，本课的动手任务会用到它：

```
<code>function wait(ms: number): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, ms));
}</code>
```

逐行读：`wait` 接收毫秒数，返回一个 `Promise<void>`（"只会兑现、不带具体值的小票"）；`setTimeout` 在 `ms` 毫秒后调用 `resolve`，`resolve` 一被调用，小票就兑现了。`new Promise` 的完整写法后面用到再细讲，今天先会用它。

## 3. async / await：写异步代码的标准姿势

两个关键字，规则各一条：

- **`async`** 标在函数前面：这个函数的返回值自动变成 Promise。你 `return "你好"`，调用方拿到的是 `Promise<string>`。
- **`await`** 写在 Promise 前面：在这里等它出结果，再把结果拿出来。`await` 只能写在 `async` 函数的内部。

```
<code>async function greet(): Promise<string> {
  await wait(1000);        // 等 1 秒，但不冻住整个程序
  return "你好，刘杰！";     // 调用方实际拿到 Promise<string>
}</code>
```

最关键的一点：`await` 的"等"不是同步那种冻住全程序的等。当前函数暂停，程序其他部分照常运转——这就是"拿小票离开柜台"。

如果忘了写 `await`，你拿到的不是结果，而是那张还没兑现的小票本身：

```
<code>console.log(greet());        // Promise { <pending> } —— 打印的是小票
console.log(await greet());  // 你好，刘杰！ —— await 把结果取了出来</code>
```

## 4. 动手：把 Tool 改成异步形态

真实 Agent 的工具全是异步的。现在把你的三文件项目升级成同样的形态。

**第一步**，`tool-types.ts`：`execute` 的返回类型从 `string` 改为 `Promise<string>`：

```
<code>export interface Tool {
  name: string;
  description: string;
  execute: (args: Record<string, any>) => Promise<string>;
}</code>
```

**第二步**，`tools.ts`：给每个 `execute` 加上 `async`，并新增一个模拟网络耗时的工具：

```
<code>import { Tool } from "./tool-types";

function wait(ms: number): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

export const calculator: Tool = {
  name: "calculator",
  description: "计算两个数的和",
  execute: async (args) => `结果是 ${Number(args.a) + Number(args.b)}`
};

export const greeter: Tool = {
  name: "greeter",
  description: "向指定的人问好",
  execute: async (args) => `你好，${args.name}！`
};

export const slowGreeter: Tool = {
  name: "slow-greeter",
  description: "模拟网络请求：延迟 1 秒后问好",
  execute: async (args) => {
    await wait(1000);   // 模拟一次网络往返的耗时
    return `你好，${args.name}！（这条问好等了 1 秒）`;
  }
};</code>
```

**第三步**，`main.ts`：`runTool` 同样改异步，再用一个 `async main()` 串起所有调用：

```
<code>import { Tool } from "./tool-types";
import { calculator, greeter, slowGreeter } from "./tools";

const toolRegistry: Record<string, Tool> = {
  calculator,
  greeter,
  "slow-greeter": slowGreeter,
};

async function runTool(name: string, args: Record<string, any>): Promise<string> {
  const tool = toolRegistry[name];
  if (!tool) return `错误：找不到名为 "${name}" 的工具`;
  return await tool.execute(args);
}

async function main() {
  console.log("开始调用工具……");
  console.log(await runTool("calculator", { a: 10, b: 20 }));
  console.log(await runTool("greeter", { name: "刘杰" }));
  console.log(await runTool("slow-greeter", { name: "刘杰" }));
  console.log("全部完成");
}

main();</code>
```

注意 `main()` 这个壳：`await` 只能待在 `async` 函数里，所以入口逻辑要包进一个 `async` 函数再调用它。这是真实项目的常见写法。

::: warning 动手任务（验收清单）

1. 按上面三步改造 `tool-types.ts` / `tools.ts` / `main.ts`。
2. 运行 `npm run start`：看到"开始调用工具……"、两条立即出现的结果、**停顿约 1 秒后**出现的 slow-greeter 结果、最后"全部完成"。
3. 运行 `npx tsc --noEmit`，确认没有任何输出（类型全部通过）。
4. **忘写 await 实验**：把 `main()` 里 `runTool("greeter", ...)` 前面的 `await` 删掉，再运行 `npm run start`，观察这一行变成了什么；然后把 `await` 加回去。

**贴回给我**：① `npm run start` 的正常输出；② 删掉 `await` 后那一行变成了什么；③ 用一句话说：`await` 做了什么？

:::

## 小测

**1. 调用一个 `async` 函数，你拿到的是什么？**

- A. 一个 Promise 对象
- B. 函数最终结果值
- C. 一个 undefined 值
- D. 一个回调函数值

::: details 点开核对答案

**答案：A（一个 Promise 对象）** —— async 函数的返回值会自动包成 Promise：你 return string，调用方拿到 Promise&lt;string&gt;。

:::

**2. 忘记写 `await` 就打印一个 Promise，会看到什么？**

- A. 程序报错并退出
- B. 自动等待再打印
- C. 打印 undefined 值
- D. Promise { &lt;pending&gt; }

::: details 点开核对答案

**答案：D（Promise { &lt;pending&gt; }）** —— 忘了 await，拿到的是还没兑现的 Promise 本身，打印出来就是 Promise { &lt;pending&gt; }。

:::

**3. 下面哪个不是 Promise 的状态？**

- A. pending（等待中）
- B. fulfilled（已成功）
- C. finished（已结束）
- D. rejected（已失败）

::: details 点开核对答案

**答案：C（finished（已结束））** —— Promise 只有三种状态：pending（等待中）、fulfilled（已成功）、rejected（已失败），没有 finished。

:::

**4. `await` 允许写在哪里？**

- A. 任何函数的内部都行
- B. async 函数的内部
- C. 文件最顶层的区域
- D. if 语句的条件里面

::: details 点开核对答案

**答案：B（async 函数的内部）** —— await 只能写在 async 函数内部；文件顶层想用，就包一个 async main() 再调用它。

:::

## 回忆挑战（遮住上文，先默写再对照）

**1. 默写最小骨架：一个延迟 1 秒后返回问好的 async 函数，以及用 await 取出它的结果并打印的那行调用。**

::: details 显示答案

```
<code>async function greet(): Promise<string> {
  await wait(1000);
  return "你好，刘杰！";
}

console.log(await greet());   // 必须待在 async 函数里</code>
```

:::

**2. 不看正文，各用一句话说：Promise 是什么？`await` 做了什么？**

::: details 显示答案

Promise 是"未来结果的凭证"（小票），有 pending / fulfilled / rejected 三种状态。`await` 写在 Promise 前面：暂停当前函数等小票兑现、取出结果，但不冻住整个程序。

:::

::: info 面试怎么考

"同步和异步的区别""Promise 有哪几种状态""async/await 和 Promise 是什么关系"是三道经久不衰的基础题。更高阶的加分项是讲项目时自然带出："我的工具接口 `execute` 返回 `Promise<string>`，因为真实工具调用——网络请求、文件读写——全是异步的。"你现在的代码已经能支撑这句话了。

:::
