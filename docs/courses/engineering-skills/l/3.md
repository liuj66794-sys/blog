第三课：使用 to-spec 生成 PRD 第三课：使用 to-spec 生成 PRD 上一课你用 /grill-with-docs 把模糊想法磨清楚了。这一课学习下一步： 怎么用 /to-spec 把讨论结果合成为一份正式的 PRD/spec。 主源推荐（Primary Source） 本课内容基于官方 skill 定义，建议精读原文： to-spec/SKILL.md （本地 ~/.agents/skills/to-spec/SKILL.md ）。 1. to-spec 是什么？ /to-spec 会把当前对话和代码库理解合成为一份 PRD（Product Requirements Document，产品需求文档）。 它 不再 interview ，只是把已经确定的东西写成结构化文档。 写完后，spec 会发布到项目的 issue tracker（问题追踪系统），并打上 ready-for-agent 标签， 供后续 /to-tickets 拆分。 2. 前置条件 /to-spec 假设项目已经运行过 /setup-matt-pocock-skills 。 如果没有，agent 会提示你先配置 issue tracker 和 triage labels（分类标签）。 3.
