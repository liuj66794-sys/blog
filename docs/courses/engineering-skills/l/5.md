第五课：使用 implement 完成实现 第五课：使用 implement 完成实现 上一课你用 /to-tickets 把 spec 拆成了一组带阻塞边的 ticket，发布到了 issue tracker。 这一课学习主线的最后一环：怎么用 /implement 按 frontier（前沿）逐个领取 ticket， 把代码写出来、测好、审查完、提交。 主源推荐（Primary Source） 本课内容基于官方 skill 定义，建议精读原文： implement/SKILL.md 、 tdd/SKILL.md 、 code-review/SKILL.md （本地 ~/.agents/skills/ 下同名目录）。 tdd 目录下还有 tests.md （好测试示例）和 mocking.md （mock 准则）两份延伸阅读。 1. implement 是什么？ /implement 根据 spec 或 ticket 完成实现工作。它是主流程 idea → ship 的“ship”端： 输入是 tracker 上 agent-ready 的 ticket，输出是提交到当前分支的、经过审查的代码。 有意思的是， /implement 的 SKILL.md 本身非常短——它只有五条规则。 它是一个 编排者 ：真正的深度在它调用的两个 skill 里—— /tdd （怎么写实现）和 /code-review （怎么收尾）。 所以这一课的大部分内容，是学这两个被驱动的 skill。 2. implement 的五条规则 SKILL.md 全文就这么多，但每条都有讲究： 实现 spec/ticket 描述的工作 ——不多做，也不少做。范围由 ticket 的验收标准界定。 尽可能用 /tdd ，在预先约定的 seam（测试边界）上写测试 ——seam 要和用户确认过才能用。 验证节…
