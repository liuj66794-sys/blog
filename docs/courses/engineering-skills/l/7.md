第七课：使用 wayfinder 规划大型模糊项目 第七课：使用 wayfinder 规划大型模糊项目 上一课的 /diagnosing-bugs 处理的是「东西坏了」的入口。这一课是入口场景系列的第二课， 处理另一种开局： 一个想法太大了，一个 agent session 装不下，而且从这里到目的地的路还看不见 。 直接 grill → to-spec 的主流程走不动它——spec 的前提是路已经清晰。 这种时候用 /wayfinder ：先把「路」本身画出来，再谈施工。 主源推荐（Primary Source） 本课内容基于官方 skill 定义，建议精读原文： wayfinder/SKILL.md （本地 ~/.agents/skills/wayfinder/SKILL.md ）。 建议完整读一遍原文，尤其是 Ticket Types 和 Fog of war 两节。 1. wayfinder 是什么？ /wayfinder 把一大块模糊的工作绘制成 issue tracker 上的一张 共享地图（shared map） ， 然后一张一张地解决地图上的 决策票（decision ticket） —— 决议的结果是「一个决定」，而不是「一片要施工的功能切片」——直到通往目的地的路清晰为止。 原文有一个定位性原则： plan, don't do（只规划，不施工） 。 地图画完的标志是「出发之前再没有什么需要决定的了」。如果你感到一股「别画了直接干吧」的冲动， 那恰恰是信号：你已经走到地图边缘，该交接给主流程（to-spec → to-tickets → implement）了。 个别工程可以在地图的 Notes 里声明例外（把施工也带进地图），但默认产出的是决策，不是交付物。 2. 地图：先命名目的地 绘制地图的第一个动作是 命名 destination（目的地） ——它…
