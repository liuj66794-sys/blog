第四课：使用 to-tickets 拆分任务 第四课：使用 to-tickets 拆分任务 上一课你用 /to-spec 把 grilling 的结果合成了一份 PRD。 这一课学习主线的下一步：怎么用 /to-tickets 把 spec 拆成一组 tracer bullet（曳光弹） 式的 ticket，让每个 ticket 都能被 agent 独立领取实现。 主源推荐（Primary Source） 本课内容基于官方 skill 定义，建议精读原文： to-tickets/SKILL.md （本地 ~/.agents/skills/to-tickets/SKILL.md ）。 建议完整读一遍原文，尤其是 wide refactor 段落的细节。 1. to-tickets 是什么？ /to-tickets 把一份 spec、计划或当前对话拆成一组 ticket 。 每个 ticket 是一个 vertical slice（垂直切片），并声明自己的 blocking edges（阻塞边）——即哪些 ticket 必须先完成，它才能开始。 拆分确认后，ticket 会发布到项目的 issue tracker（问题追踪系统）， 并打上 ready-for-agent 标签，供后续 /implement 逐个领取。 2. 前置条件 和 /to-spec 一样， /to-tickets 假设项目已经运行过 /setup-matt-pocock-skills ，即已配置好 issue tracker 和 triage labels（分类标签）。 3. 核心概念：垂直切片 拆分的第一原则是 垂直切，而不是水平切 。每个切片要满足四条规则： 窄但完整 ：切穿所有层（schema、API、UI、测试），而不是只切某一层。 独立可验证 ：一个切片完成后，可以单独演示或验证。 适配单个上下…
